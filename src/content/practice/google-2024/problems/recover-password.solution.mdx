## Approach: topological sort

Each fragment is a chain of "comes before" constraints. For the fragment `"fli"`, `f` comes before `l` and `l` before `i` (and so `f` before `i`). Treat characters as nodes of a directed graph with an edge `a → b` whenever `a` comes right before `b` in some fragment. You only need consecutive pairs, because the order is transitive.

A password consistent with all fragments is exactly a **topological order** of this graph. Build it with Kahn's algorithm:

1. Count each character's in-degree: how many characters must come before it.
2. Repeatedly take a character with in-degree `0`, append it to the password, and decrement the in-degree of everything after it.

To get the lexicographically smallest password, always take the **smallest** available character. Choosing a smaller character now can never block a better choice later. Any character that's available now stays available until you take it, so the greedy choice is optimal at each position.

The Python solution keeps the available characters in a min-heap. The JavaScript solution scans for the smallest, which is fine because there are at most 62 distinct characters.

## Complexity

With `L` the total length of all fragments and `V <= 62` distinct characters:

- **Time:** `O(L + V log V)` with a heap (`O(L + V²)` with the scan).
- **Space:** `O(V + E)` for the graph, where `E <= L`.

## About the follow-up

The order is unique exactly when, at every step of Kahn's algorithm, **only one** character is available. If two are ever available at once, they could be swapped, so the password isn't determined.
