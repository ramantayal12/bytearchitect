## Approach: count points, anchor on one side

Store how many times each point was added, in a hash map from `(x, y)` to a count.

For a query `(x, y)`, an axis-aligned square is fixed once you know one more corner. The simplest choice is the corner on the **same vertical line**, `(x, y2)` with `y2 ≠ y`. That fixes the side length `d = y2 - y`, and the square extends either to the right or to the left:

- right: the other corners are `(x + d, y)` and `(x + d, y2)`,
- left: the other corners are `(x - d, y)` and `(x - d, y2)`.

Multiplying the three stored counts gives the number of ways to pick copies of those corners. Sum over every distinct `y2` stored with the same `x`, and both directions.

To find the candidates `(x, y2)` quickly, also keep, per `x`, the set of `y` values that have been added.

## Complexity

- `add`: `O(1)`.
- `count`: `O(k)`, where `k` is the number of distinct points on the query's vertical line (at most `1001`).
- **Space:** `O(n)` for the distinct points.

Checking every triple of stored points would be `O(n³)` per query.

## About the follow-up

A rotated square is fixed by any two of its corners. For the query `q` and each stored point `p`, treat `q → p` as a side: rotating that vector by 90° in either direction gives the two remaining corners, which you look up in the map. That's `O(n)` per query. Each square is found exactly twice (once from each neighbour of `q`), so halve the total.
